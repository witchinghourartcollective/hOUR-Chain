# HBC-020 First Release Pilot Template

Status: ready for release selection and contributor confirmation.

## Pilot rule

The first pilot must be a real music, visual-art, or performance release. MIRRORIZM token activity and the HOUR/HBC protocol token decision remain separate.

## Required release data

- Release title, version, artist/project name and target date
- Work and recording identifiers where available
- Contributors, roles, rights categories and split percentages totaling 100% per category
- Source evidence for credits, ownership, approvals and final media
- Consent state and timestamp for every contributor
- Provenance events and expected settlement receipt
- Payout preference for each payee

## Wallet policy

A collaborator does **not** need a crypto wallet to be credited, approve splits, or appear in the rights/provenance record.

Use a stable participant ID and verified contact/consent record first. For payouts, each contributor chooses one of:

1. supply a wallet they control;
2. defer onchain payout while value accrues in a non-custodial claim record;
3. receive an ordinary fiat payout where supported; or
4. opt into an assisted/managed-wallet onboarding flow with explicit consent and recovery terms.

Witching Hour must not silently create a self-custody wallet, retain a contributor's seed phrase/private key, or imply that a managed account is self-custody. Wallet onboarding is a product/compliance workstream, not a prerequisite for the pilot fixture.
